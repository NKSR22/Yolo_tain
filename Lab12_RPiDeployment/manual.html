LAB 12 · Raspberry Pi deployment

Export ONNX แล้วนับวัตถุต่อคลาสบน Raspberry Pi

best.pt (Lab 10–11) → best.onnx → ซ้อมบนคอม → รันบน Pi + กล้อง USB · นับเมื่อวัตถุข้ามเส้น

หลักการนับ

สคริปต์ conveyor_count.py ตรวจจับทุกเฟรม แล้วจับคู่กรอบในเฟรมนี้กับเฟรมก่อนด้วยจุดศูนย์กลางที่ใกล้ที่สุด (track) วัตถุแต่ละชิ้นจะถูกนับครั้งเดียวตอนจุดศูนย์กลางข้ามเส้นนับสีเหลือง ไม่ว่าจะข้ามจากซ้ายหรือขวา สวิตช์กลับทิศสายพานจึงไม่ต้องตั้งค่าอะไร ทิศจะถูกบันทึกไว้เป็น + (ซ้าย→ขวา) หรือ - (ขวา→ซ้าย)

คลาสที่นับใช้เสียงข้างมากตลอดช่วงที่ track นั้นอยู่ในภาพ ถ้าโมเดลทายผิดเฟรมเดียวตอนข้ามเส้น ผลนับก็ไม่เปลี่ยน

1. Export เป็น ONNX บน Windows

คัดลอก best.pt ที่ผ่าน Lab 11 แล้วไปไว้ที่ Lab12_RPiDeployment\best.pt แล้วรัน:

.\Lab12_RPiDeployment\scripts\export_custom_onnx.bat

ได้ Lab12_RPiDeployment\best.onnx ขนาดภาพ 640 ล็อกตายตัวในไฟล์ ถ้าอยากเปลี่ยนขนาดต้อง export ใหม่

2. ซ้อมนับบนคอมก่อน

ใช้ไฟล์ ONNX ตัวเดียวกับที่จะส่งไป Pi และรันบน CPU เหมือน Pi เปิดสวิตช์สายพานแล้วรัน:

.\Lab12_RPiDeployment\scripts\run_count.bat 0
.\Lab12_RPiDeployment\scripts\run_count.bat "C:\data\belt clip.mp4"

หน้าต่าง conveyor count แสดงกรอบ เส้นนับ จำนวนต่อคลาส และ FPS กด q เพื่อหยุด ตัวอย่างข้างล่างเป็นผลจริงตอนทดสอบสคริปต์ด้วยโมเดล COCO (yolo11n) กับวิดีโอจำลองที่รถบัสวิ่งไปแล้ววิ่งกลับ (คนสองคนที่ยืนหน้ารถในภาพก็ถูกนับด้วย):

21:22:38  #1    bus              +  (total bus: 1)
21:22:38  #3    person           +  (total person: 1)
21:22:39  #4    person           +  (total person: 2)
21:22:42  #6    person           -  (total person: 3)
21:22:42  #7    person           -  (total person: 4)
21:22:42  #8    bus              -  (total bus: 2)

=========== summary ===========
  bus                      2
  person                   4
  total                    6
  average FPS             27.1
ส่วนความหมาย
#1หมายเลข track ของวัตถุชิ้นนั้น ถ้าชิ้นเดียวได้หลายหมายเลข แปลว่า track หลุด (ดู Troubleshooting)
+ / -ทิศที่ข้ามเส้น ซ้าย→ขวา / ขวา→ซ้าย
average FPSความเร็วจริง ถ้าต่ำมากเทียบกับความเร็วสายพาน วัตถุอาจกระโดดไกลเกินระหว่างเฟรมจนจับคู่ไม่ได้

ทุกการนับถูกบันทึกลง Lab12_RPiDeployment\counts_windows.csv (คอลัมน์ time, track_id, class, direction) เปิดด้วย Excel ได้

3. ปรับเส้นนับ

ตัวเลือกค่าเริ่มต้นใช้เมื่อ
--line 0.40.5ย้ายเส้นนับ (สัดส่วนของความกว้างภาพ 0–1) วางเส้นตรงที่โมเดลตรวจจับได้มั่นคงที่สุด
--axis yxกล้องวางให้สายพานวิ่งขึ้น↔ลงในภาพ เส้นนับจะเป็นแนวนอน
--conf 0.50.4มีกรอบผีโผล่ (นับเกิน) ให้เพิ่ม · วัตถุจริงหลุดบ่อย ให้ลด
--no-show-ไม่เปิดหน้าต่าง แสดงผลในเทอร์มินัลอย่างเดียว
.\Lab12_RPiDeployment\scripts\run_count.bat 0 --line 0.4 --conf 0.5

4. ส่งไป Raspberry Pi

ต้องทำ Lab 7 บน Pi ตัวนี้มาก่อน สคริปต์ใช้ Python environment ~/Lab7_RaspberryPi/venv ตัวเดิม จาก Windows:

.\Lab12_RPiDeployment\scripts\copy_to_pi.bat admin@mIoT.local

ไฟล์จะไปอยู่ที่ ~/Lab12_RPiDeployment/ บน Pi จากนั้นที่หน้าจอของ Pi (ไม่ใช่ SSH) เปิด Terminal แล้วรัน:

~/Lab12_RPiDeployment/scripts/run_count_pi.sh
~/Lab12_RPiDeployment/scripts/run_count_pi.sh 0 --line 0.4

ถ้ารันผ่าน SSH สคริปต์จะรู้เองว่าไม่มีจอ และนับในเทอร์มินัลอย่างเดียว (หยุดด้วย Ctrl+C) ไฟล์ log อยู่ที่ ~/Lab12_RPiDeployment/counts_<วันเวลา>.csv

ยังไม่ได้ทดสอบบน Pi กับโมเดลและสายพานจริง ส่วนที่ทดสอบแล้วบน Windows: ตรรกะการนับ (8 กรณี รวมกลับทิศ/วัตถุสองชิ้นคู่กัน/ตรวจจับหลุดชั่วคราว), export, และการนับจากวิดีโอด้วย ONNX บน CPU · FPS บน Pi 5 จะต่ำกว่าบนคอมมาก วัดจริงแล้วบันทึกไว้

Troubleshooting

อาการสาเหตุ / วิธีแก้
ชิ้นเดียวนับสองครั้งtrack หลุดตรงเส้นนับ: โมเดลตรวจจับไม่ติดต่อกัน ลด --conf หรือย้าย --line ไปจุดที่ตรวจจับได้มั่นคง
วัตถุผ่านแต่ไม่นับโมเดลไม่เห็นวัตถุตอนอยู่ใกล้เส้น หรือ FPS ต่ำจนวัตถุกระโดดเกิน 15% ของภาพระหว่างเฟรม ลดความเร็วสายพานไม่ได้ จึงต้องเพิ่ม FPS (export ขนาดเล็กลงใน Lab 6) หรือใช้ AI HAT (Lab 8)
นับผิดคลาสกลับไปเก็บภาพคลาสนั้นเพิ่มใน Lab 9 แล้วเทรนใหม่ ตรวจว่าแสงและมุมกล้องตอนเก็บภาพตรงกับตอนนี้
no data transfer registered บนคอมONNX ถูกส่งไป GPU สคริปต์บังคับ CPU ให้แล้วสำหรับไฟล์ .onnx ถ้ายังเจอ ตรวจว่าใช้สคริปต์เวอร์ชันล่าสุด
Python environment not found บน Piยังไม่ได้ทำ Lab 7: cd ~/Lab7_RaspberryPi/scripts && ./setup_pi.sh
