เอกสารนี้คือ **แผนและตัวติดตามงาน** สำหรับการยกระดับคู่มือ (`LabN/manual.html`)
จาก "ชุดคำสั่งให้พิมพ์ตาม" ให้เป็น "คู่มือการเรียนรู้ที่สมบูรณ์"

เปิดไฟล์นี้ก่อนเริ่มงานทุกครั้ง เพื่อดูว่าทำถึงไหนแล้วและขั้นตอนต่อไปคืออะไร

## 1. เป้าหมายของคู่มือแต่ละ Lab

คู่มือที่ถือว่า "สมบูรณ์" ต้องมีครบ 4 อย่างนี้ในทุก Step:

| # | องค์ประกอบ | เหตุผล |
|---|---|---|
| 1 | **คำสั่งที่ต้องพิมพ์** | ขึ้นต้นด้วย `.\` เสมอ (PowerShell ไม่รันไฟล์ในโฟลเดอร์ปัจจุบันถ้าไม่มี) |
| 2 | **ผลลัพธ์จริงบนหน้าจอ** (`<pre class="out">`) | นักศึกษาเทียบกับจอตัวเองได้ว่ามาถูกทางไหม |
| 3 | **ตารางอ่านผลให้เป็น** | บอกว่าแต่ละบรรทัด/ตัวเลขในผลลัพธ์แปลว่าอะไร และต้องดูตัวไหนเป็นพิเศษ |
| 4 | **`🔍 ในสคริปต์มีอะไร`** (`<div class="walk">`) | แกะสคริปต์ทีละบรรทัด ให้แก้เองเป็น ไม่ใช่แค่รันตาม |

บวกกับ **ภาพประกอบ** ในจุดที่คำอธิบายอย่างเดียวไม่พอ (ผลลัพธ์ที่เป็นภาพ, หน้าต่างโปรแกรม GUI, กราฟ)
และ **ตาราง Troubleshooting** ที่มาจากปัญหาที่เจอจริงตอนทดสอบ

### ขั้นที่ 2 — เก็บภาพประกอบ

ใช้ `docs/shoot.py` ทุกกรณี (รายละเอียดข้อ 5)

- **ภาพหน้าต่าง GUI** → ต้องให้ผู้ใช้ช่วย เป็นกรณีเดียวที่เหลือ

  - แคปที่ต้องคาเมาส์ไว้ที่เดิม: `shoot.py grab labelImg <ชื่อ> -d 10`
  - อย่าใช้ `Alt+PrintScreen` กับโปรแกรม Qt — ปุ่ม `Alt` ไปเปิดแถบเมนู ทำให้ภาพที่ต้องการหาย

## 5. เครื่องมือช่วย

ทุกอย่างรวมอยู่ใน **`docs/shoot.py`** ตัวเดียว ทุกโหมดเซฟลง `docs/images/` ให้อัตโนมัติ
(ย่อขนาดให้เอง ตั้งชื่อตามที่ระบุ)

| โหมด | ใช้ทำอะไร |
|---|---|
| `run <ชื่อ> -t "หัวข้อ" -- <คำสั่ง>` | **รันคำสั่งแล้วเรนเดอร์ output เป็นภาพหน้าต่าง terminal** — ไม่ต้องพึ่งคนแคปเลย |
| `text <ชื่อ> -f <ไฟล์log> -t "หัวข้อ"` | เรนเดอร์ log ที่เก็บไว้แล้วเป็นภาพ (ใช้กับคำสั่งที่รันนานอย่างการ train) |
| `pick <ไฟล์ต้นทาง> <ชื่อ> -w 900` | ก๊อปภาพผลลัพธ์จาก `runs\` มาย่อขนาด |
| `grab <ชื่อหน้าต่าง> <ชื่อ> -d 8` | นับถอยหลังแล้วจับภาพหน้าต่าง สำหรับเคสที่ต้องคาเมาส์ไว้ที่เดิม |
| `clip <ชื่อ>` | ดึงภาพจาก clipboard (หลังผู้ใช้กด `Win+Shift+S`) |

ตัวอย่าง:

```powershell
# ภาพ terminal จากการรันจริง - อัตโนมัติทั้งหมด
python docs/shoot.py run lab4_train_baseline -t "> .	rain_baseline.bat" -- venv/Scripts/yolo.exe detect train data=african-wildlife.yaml epochs=50

# คำสั่งที่รันนาน: เก็บ log ก่อนแล้วค่อยเรนเดอร์
python docs/shoot.py text lab4_train_baseline -f log.txt -t "> .	rain_baseline.bat" --max-lines 30

# ภาพผลลัพธ์ที่โปรแกรมสร้างเอง
python docs/shoot.py pick runs/detect/train/results.png lab4_results -w 900
```

**โหมด `run` / `text` แทนการแคปหน้าจอ terminal ได้ทั้งหมด** — รองรับสี ANSI ของ ultralytics,
รวมบรรทัด progress bar ที่เขียนทับกันด้วย `
` ให้เหลือสถานะสุดท้าย, ตัดบรรทัดยาวที่ขอบ
และย่อ log ยาว ๆ ด้วยเครื่องหมาย `... (N lines omitted) ...` ตรงกลาง

เหลือแค่ **หน้าต่างโปรแกรม GUI** (labelImg, หน้าต่าง webcam) ที่ยังต้องใช้ `grab` / `clip`
ซึ่งต้องรบกวนผู้ใช้ — ส่วนนี้ของ Lab 0-3 เก็บครบแล้ว

### สิ่งที่ต้องสร้างเพิ่มจากการตัดสินใจนี้

1. **`Lab0_Setup/scripts/prefetch.bat`** — สคริปต์ตัวเดียวจบให้นักศึกษารันที่บ้านก่อนเข้าคลาส
   โหลด `yolo11n.pt` + dataset ทั้ง 2 ชุด + ภาพตัวอย่าง Lab 2 + ติดตั้ง/patch labelImg
   แล้วพิมพ์สรุปว่าครบไหม (รูปแบบเดียวกับ `check_env.py`)
   เพิ่มหัวข้อ "ทำก่อนเข้าคลาส" ในคู่มือ Lab 0

2. **Lab 3 — ฟีเจอร์ซ่อนเฉลยแล้วเทียบทีหลัง** (ตกลงว่าเอา)
   - สคริปต์ดึงรูปจาก `african-wildlife` มา 15-20 ใบ **โดยแยกไฟล์ label ต้นฉบับไปซ่อนไว้**
   - นักศึกษา label เองด้วย labelImg ตามปกติ
   - สคริปต์เทียบผลกับเฉลย: รายงาน IoU ของแต่ละกรอบ, วัตถุที่ลืม label, คลาสที่ทายผิด
   - จุดขาย: สอนว่า "label ที่ดีหน้าตาเป็นยังไง" ซึ่งชี้ขาดคุณภาพโมเดลมากกว่า hyperparameter
     และเป็นสิ่งที่การให้ไปถ่ายรูปเองทำไม่ได้ เพราะไม่มีเฉลย

3. **Lab 4 — เทรน 2 รอบเทียบกัน: ชุดที่ label เอง vs ชุดเต็ม**

   จุดสำคัญคือ **รูปที่นักศึกษา label ใน Lab 3 มาจาก `african-wildlife` ชุดเดียวกับที่ Lab 4 ใช้เทรน**
   เส้นเรื่องจึงไม่ขาด และยังได้บทเรียนเพิ่มฟรี:

   - **รอบที่ 1** เทรนด้วย `Lab3_CustomDataset\dataset\data.yaml` (ผลงาน label เองของนักศึกษา ~20 รูป)
   - **รอบที่ 2** เทรนด้วย `african-wildlife.yaml` (ชุดเต็ม ~1,500 รูป คลาสเดียวกันเป๊ะ)
   - เทียบ mAP กัน → เห็นด้วยตาตัวเองว่า **จำนวนข้อมูลสำคัญกว่าการปรับ hyperparameter**

   ปกติบทเรียนนี้สอนได้แค่ "บอกให้เชื่อ" แต่แบบนี้นักศึกษาเพิ่งเสีย 20 นาที label 20 รูปมาเอง
   เลยเข้าใจทันทีว่าทำไม dataset จริงถึงต้องมีหลักร้อยหลักพันรูป
   และคู่มือได้กราฟจากชุดเต็มที่มีความหมายจริงไปด้วย

   Lab 5-6 ใช้ `best.pt` จากรอบที่ 2 (ชุดเต็ม) ต่อ
   คู่มือเขียนกำกับว่าเมื่อทำโครงงานจริงให้เปลี่ยน `data=` เป็นของกลุ่มตัวเอง

**Lab 3 ที่ต้องแก้:**

1. สคริปต์ใหม่ 2 ตัว — ดึงรูปจาก `african-wildlife` พร้อมซ่อนเฉลย + เทียบผล label
2. `make_dataset_structure.bat` — `classes.txt` เริ่มต้นเปลี่ยนจาก `object`
   เป็น 4 คลาสของ african-wildlife (buffalo, elephant, rhino, zebra)
3. คู่มือ Step 2 "เก็บภาพ" — เดิมสั่งให้ถ่ายรูปเอง 100-200 ใบต่อคลาส
   ต้องเปลี่ยนเป็น "รันสคริปต์ดึงรูปฝึก" แล้วย้ายเรื่องถ่ายรูปเองไปเป็นหัวข้อสำหรับโครงงาน
4. คู่มือหัวข้อ "แหล่งดาวน์โหลดรูปภาพ" — ปรับให้ชี้มาที่สคริปต์ใหม่เป็นหลัก
   ส่วนแหล่งอื่น (Roboflow / Kaggle / Open Images) เก็บไว้เป็นทางเลือกสำหรับโครงงาน
5. ตัวอย่างในคู่มือที่ใช้ `bottle` / `can` — เปลี่ยนให้ตรงกับคลาสจริงที่นักศึกษาจะเห็น
6. **ภาพประกอบ 3 จาก 4 ใบต้องถ่ายใหม่** เพราะถ่ายไว้ตอนใช้รูป COCO กับคลาส `person`/`animal`
