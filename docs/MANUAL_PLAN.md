เอกสารนี้คือ **แผนและตัวติดตามงาน** สำหรับการยกระดับคู่มือ (`LabN/manual.html`)

## 1. เป้าหมายของคู่มือแต่ละ Lab

คู่มือที่ถือว่า "สมบูรณ์" ต้องมีครบ 4 อย่างนี้ในทุก Step:

| # | องค์ประกอบ | เหตุผล |
|---|---|---|
| 1 | **คำสั่งที่ต้องพิมพ์** | ขึ้นต้นด้วย `.\` เสมอ (PowerShell ไม่รันไฟล์ในโฟลเดอร์ปัจจุบันถ้าไม่มี) |
| 2 | **ผลลัพธ์จริงบนหน้าจอ** (`<pre class="out">`) | นักศึกษาเทียบกับจอตัวเองได้ว่ามาถูกทางไหม |
| 3 | **ตารางอ่านผลให้เป็น** | บอกว่าแต่ละบรรทัด/ตัวเลขในผลลัพธ์แปลว่าอะไร และต้องดูตัวไหนเป็นพิเศษ |
| 4 | **`🔍 ในสคริปต์มีอะไร`** (`<div class="walk">`) | แกะสคริปต์ทีละบรรทัด ให้แก้เองเป็น ไม่ใช่แค่รันตาม |

บวกกับ **ภาพประกอบ** ในจุดที่คำอธิบายอย่างเดียวไม่พอ (ผลลัพธ์ที่เป็นภาพ, หน้าต่างโปรแกรม GUI, กราฟ)
และ **ตาราง Troubleshooting** ที่มาจากปัญหาที่เจอจริงตอนทดสอบ

## 3. สูตรทำแต่ละ Lab (ทำตามลำดับนี้)

### ขั้นที่ 1 — อ่านและรันสคริปต์จริง ก่อนแตะคู่มือ

> ห้ามเขียนคู่มือจากการอ่านโค้ดอย่างเดียว **ต้องรันจริงทุกสคริปต์**
> บั๊กที่เจอมาทั้งหมดในรอบนี้ ไม่มีสักตัวที่มองออกจากการอ่านโค้ดเฉย ๆ
> (path ที่ซ้อนกัน, `data.yaml` ที่ resolve ผิดที่, labelImg ที่เด้งตอนลากกรอบ,
> แอนตี้ไวรัสบล็อกเว็บแคมแบบไม่มี error — เห็นได้จากการรันเท่านั้น)

```powershell
cd C:\dev\Yolo_tain\LabN_xxx\scripts
.\script.bat
```

- จดผลลัพธ์ทุกบรรทัดไว้ (ก๊อปจาก terminal ตรง ๆ **ห้ามพิมพ์เอง**)
- เจอบั๊ก → **แก้สคริปต์ก่อน** แล้วรันซ้ำจนผ่าน
- สิ่งที่ทดสอบเองไม่ได้ (กล้อง, GUI, Pi) ให้บันทึกไว้ว่ายังไม่ได้ทดสอบ
  **ห้ามเขียนคู่มือเหมือนทดสอบแล้ว**

### ขั้นที่ 2 — เก็บภาพประกอบ

- **ภาพผลลัพธ์ที่โปรแกรมสร้างเอง** (predict output, กราฟ, confusion matrix)
  → ก๊อปจาก `runs\` แล้วย่อด้วยสคริปต์ (ดูข้อ 5)
- **ภาพหน้าต่าง GUI** → ต้องให้ผู้ใช้แคปให้
  - แคปปกติ: `Win+Shift+S` แล้วรัน `python docs/save_screenshot.py <ชื่อ>` ดึงจาก clipboard
  - แคปที่ต้องคาเมาส์ไว้ที่เดิม: `python docs/capture_window.py labelImg <ชื่อ> 10`
    (นับถอยหลังแล้วจับภาพหน้าต่างเอง)
  - อย่าใช้ `Alt+PrintScreen` กับโปรแกรม Qt — ปุ่ม `Alt` ไปเปิดแถบเมนู ทำให้ภาพที่ต้องการหาย

### ขั้นที่ 3 — เขียนคู่มือ

1. เติมบล็อก CSS (ดูข้อ 4) ถ้ายังไม่มีในไฟล์นั้น
2. ทุก Step เติมให้ครบ 4 องค์ประกอบตามข้อ 1
3. แทรก `<figure>` พร้อม `<figcaption>` ที่ **ชี้ให้สังเกตบางอย่าง** ไม่ใช่แค่บอกว่าภาพอะไร
4. เขียนตาราง Troubleshooting จาก **ปัญหาที่เจอจริงตอนทดสอบเท่านั้น**
   พร้อมข้อความ error จริง (นักศึกษาจะได้ค้นเจอเวลาก๊อป error ไปหา)
5. ปิดท้ายด้วยกล่อง "ทดสอบแล้วบนเครื่องจริง" ระบุสเปกเครื่องและตัวเลขที่ได้จริง

### ขั้นที่ 4 — ตรวจก่อน commit

ตรวจว่าแท็กครบคู่ และ path รูปถูกต้อง:

```python
import re
from pathlib import Path
p = Path("LabN_xxx/manual.html")
t = p.read_text(encoding="utf-8")
print("divs", t.count("<div"), t.count("</div>"),
      "| figure", t.count("<figure"), t.count("</figure>"),
      "| table", t.count("<table"), t.count("</table>"))
for s in re.findall(r'<img src="([^"]+)"', t):
    print("OK " if (p.parent / s).resolve().exists() else "MISS", s)
```

- ลบไฟล์ทดสอบที่สร้างระหว่างทาง (`runs\detect\*_docs`, dataset ทดสอบ)
- แปลงไฟล์ `.bat` / `.py` ที่แก้ให้เป็น CRLF ให้ตรงกับของเดิมในรีโป
- **อัปเดตตารางสถานะในข้อ 2 และบันทึกความคืบหน้าในข้อ 7 ของไฟล์นี้**
- commit แยกต่อ Lab

## 7. การตัดสินใจเรื่อง dataset (ตกลงกันแล้ว 2026-08-30)

**ปัญหา:** คู่มือ Lab 4-10 ต้องอ้างอิงตัวเลขและกราฟจาก dataset ตัวใดตัวหนึ่ง
ถ้าใช้ชุดเล็ก (10-20 รูป) ตัวเลขที่ได้จะเป็นสัญญาณรบกวน ไม่ใช่ผลของการปรับค่า
โดยเฉพาะ Lab 4 ที่ทั้ง Lab คือการเปรียบเทียบ hyperparameter

**ที่ตัดสินใจ:** ใช้ dataset ที่ Ultralytics โหลดให้อัตโนมัติ **2 ชุดแยกกัน**
(ไม่ต้องสมัครสมาชิก ไม่ต้องมี API key แค่ใส่ชื่อในคำสั่ง `data=`)

| ใช้ที่ไหน | dataset | คลาส | ขนาดโหลด |
|---|---|---|---|
| Lab 3-6 (สอนพื้นฐาน) | `african-wildlife.yaml` | buffalo, elephant, rhino, zebra | 105 MB |
| Lab 9-10 (โครงงาน) | `construction-ppe.yaml` | helmet, gloves, vest, boots, goggles, person | 178 MB |

**เหตุผล:** african-wildlife มี 4 คลาสที่แยกออกจากกันชัดด้วยตาเปล่า ทำให้ Lab 4 เห็นความต่าง
ของ hyperparameter จริง และ Lab 5 มี confusion matrix ที่อ่านออก
ส่วน construction-ppe ใกล้เคียงงานตรวจจับในอุตสาหกรรม เหมาะกับ Lab 9-10 ที่เป็นโครงงาน

**เรื่องแบนด์วิดท์:** ให้นักศึกษาโหลดเองก่อนเข้าคลาส ไม่ต้องเตรียมไฟล์แจก

### สิ่งที่ต้องสร้างเพิ่มจากการตัดสินใจนี้

1. **`Lab0_Setup/scripts/prefetch.bat`** — สคริปต์ตัวเดียวจบให้นักศึกษารันที่บ้านก่อนเข้าคลาส
   โหลด `yolo11n.pt` + dataset ทั้ง 2 ชุด + ภาพตัวอย่าง Lab 2 + ติดตั้ง/patch labelImg
   แล้วพิมพ์สรุปว่าครบไหม (รูปแบบเดียวกับ `check_env.py`)
   เพิ่มหัวข้อ "ทำก่อนเข้าคลาส" ในคู่มือ Lab 0

2. **Lab 3 — ฟีเจอร์ซ่อนเฉลยแล้วเทียบทีหลัง** (ตกลงว่าเอา)
   - สคริปต์ดึงรูปจาก `african-wildlife` มา 15-20 ใบ **โดยแยกไฟล์ label ต้นฉบับไปซ่อนไว้**
   - นักศึกษา label เองด้วย labelImg ตามปกติ
   - สคริปต์เทียบผลกับเฉลย: รายงาน IoU ของแต่ละกรอบ, วัตถุที่ลืม label, คลาสที่ทายผิด
   - จุดขาย: สอนว่า "label ที่ดีหน้าตาเป็นยังไง" ซึ่งชี้ขาดคุณภาพโมเดลมากกว่า hyperparameter
     และเป็นสิ่งที่การให้ไปถ่ายรูปเองทำไม่ได้ เพราะไม่มีเฉลย

3. **Lab 4-6 เปลี่ยนไปใช้ `african-wildlife.yaml`**
   เดิมสคริปต์ชี้ไปที่ `Lab3_CustomDataset\dataset\data.yaml` ซึ่งเป็นชุดฝึก label 15-20 รูป
   เล็กเกินกว่าจะให้ผลที่มีความหมาย
   **ข้อเสนอ:** ตั้ง `data=african-wildlife.yaml` เป็นค่าเริ่มต้น แล้วในคู่มือเขียนกำกับว่า
   เปลี่ยนเป็น dataset ของกลุ่มตัวเองได้โดยแก้ค่า `data=` — คงเนื้อหาการสอนไว้
   แต่ได้กราฟและตัวเลขที่มีความหมายจริงในคู่มือ
